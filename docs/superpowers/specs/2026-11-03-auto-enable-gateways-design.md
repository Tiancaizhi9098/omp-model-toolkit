# 新网关模型自动启用

## 目标

保留已有模型白名单，同时让以后新添加并通过 OMP 认证检查的网关模型自动加入启用范围。模型提示词列表跟随相同的有效范围。

## 方案选择

- 手动加入每个新网关：实现最小，但每次配置网关后仍需重新勾选。
- 识别新网关并自动追加其模型：用户已选择此方案；同时保存已见网关记录，保护已有手动选择。
- 清空白名单恢复全部：会重新启用此前取消的旧模型，不采用。

## 行为

1. 以完整 provider ID 区分网关。首次发现一个新的可用 provider，将它当时可用的对话模型追加到原生 enabledModels，不覆盖原有条目。
2. 已见网关记录按 OMP profile 保存。取消勾选、网关暂时离线或重启，不会导致已取消的旧模型被重新开启。同一 provider 后续增加模型，仍按已有网关处理，保留手动选择语义。
3. 初次升级先记录已有网关，包括现有 provider/model 选择中暂时离线的网关，避免误把历史取消的网关当作新增。对本次用户明确要求恢复的新网关，升级时单独加入现有范围。
4. 在启动、打开两个插件命令时同步；会话空闲时检查已加载的模型目录，处理运行中增加的网关。读取目录不会发起推理请求或主动访问第三方接口。
5. 全部模型模式保持全部模型模式；更高优先级的项目或运行时配置照常有效，自动同步不会覆盖它们。
6. 不自动复制提示词文件、不跨 provider 绑定提示词，不添加持续状态栏文字，不改 OMP 本体或原生启动显示设置。

## 实现边界

增加独立的已见网关状态文件和同步模块；通过 OMP 原生设置接口更新范围。保留现有命令和文件格式。多个会话与手动保存串行协调，防止旧快照覆盖新选择。卸载插件后已保存的 enabledModels 仍遵循原生行为。

## 验证

使用真实 OMP loader、settings 和 matcher 验证：新网关自动出现；已有禁用模型不恢复；重复同步不追加重复条目；取消勾选后重启仍禁用；配置覆盖不被突破；提示词列表即时联动。继续运行现有测试、严格类型检查和本机模拟请求，发布合并插件的新版本。
